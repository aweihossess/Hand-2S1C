## 1. 目标与硬约束

1. 磁编闭环链路必须高优先级、低延时、可预测，保障驱动安全。
2. 触觉数据要支持上位机实时显示，体验目标至少达到可连续观察。
3. 防反转（x1）需要在通信抖动下保持有效拦截。
4. 算法链路设计要可落地、可测量、可验收。

---

## 2. 总体方案（三条并行链路）

### 2.1 控制安全链路（最高优先级）

1. S3 采集磁编并发送到 P4（CAN）。
2. P4 以固定周期执行求解与电机下发。
3. 此链路只承载闭环控制必需信息，严格限流其他数据流对它的影响。

### 2.2 触觉显示链路（中优先级）

1. S3 采集触觉后形成 summary 帧（优先）或 full dump 帧（调试）。
2. 触觉通过 CAN 到 P4，再由串口上传到上位机。
3. 上位机按显示帧率刷新热力图，采用“最新帧覆盖”策略。

### 2.3 配置与保护链路（安全约束）

1. 上位机下发 tendon guard（`enabled/sign/x1_abs`）。
2. P4 本地执行 x1 边界判定，拦截 release。
3. 配置版本、ACK、重发策略用于保障重启后的防护连续性。

---

## 3. 周期与优先级基线

| 模块 | 建议频率 | 优先级 | 说明 |
|---|---:|---|---|
| 磁编采集（S3） | 200 Hz | 最高 | 为闭环提供更新原始量 |
| 磁编上报（S3->P4） | 100~200 Hz | 最高 | 可按稳定性从 100 Hz 起步 |
| 求解与控制（P4） | 100 Hz（10 ms） | 最高 | 固定周期执行 |
| 触觉 summary 上报 | 20~50 Hz | 中 | 先满足显示与事件检测 |
| 触觉 full dump | 10~20 Hz | 低 | 调试/记录阶段使用 |
| UI 渲染 | 20~30 FPS | 中 | 保证观察连续性 |

说明：`2 Hz` 仅用于链路通断验证，无法满足实时触觉显示目标。

## 4. 带宽预算与可行性判断

CAN 速率基线：`1 Mbps`。

### 4.1 磁编链路预算

1. 21 路磁编，2 字节/路，单周期负载 42 字节。
2. 当前编码方式约 6 帧/周期。
3. 100 Hz 时约 600 帧/s，200 Hz 时约 1200 帧/s。
4. 该负载可作为系统常驻高优先级流。

### 4.2 触觉 summary 预算

1. 15 个触觉模块，每模块 3 轴全局值，共 45 字节/周期。
2. 同样约 6 帧/周期。
3. 20~50 Hz 下对总线压力可控，适合在线显示。

### 4.3 触觉 full dump 风险

1. 依据当前结构体，全量触觉体量远大于 summary。
2. 该模式会显著提高 CAN 占用，容易挤压控制链路余量。
3. 结论：full dump 作为低频调试通道，控制运行期以 summary 为主。

## 5. 同步机制与锁策略（关键）

## 5.1 原则

1. 高频闭环路径优先使用队列快照，避免在控制周期里等待锁。
2. 多任务共享数组/结构体时，使用互斥锁或双缓冲保护一致性。
3. 临界区保持短小，避免长时间持锁。

## 5.2 推荐实现

1. 磁编主链路：`单写者 + QueueOverwrite(最新帧)`。
2. 求解器读取：周期内读“最新可用快照”，丢旧帧可接受。
3. 触觉缓存：采集任务写缓存，上传任务读缓存，使用 mutex 保护整包复制。
4. 配置参数（x1、目标角、模式位）：使用 mutex 或版本号+双缓冲。

## 5.3 设计收益

1. 控制周期抖动可控。
2. 共享数据一致性可控。
3. 通信峰值时系统行为更稳定。

## 6. 防反转（x1）在高频控制下的评估

## 6.1 判定链路

1. 上位机下发 `CMD_TENDON_GUARD`。
2. P4 接收后写入 `tendon_guard_enabled/sign/x1_abs`。
3. P4 求解周期内执行 x1 判定并触发 hold。

## 6.2 延时相关风险来源

1. 反馈新鲜度：采样与求解存在周期差。
2. 执行延时：判定命中到电机实际减速存在物理滞后。
3. 边界余量：若 margin 为 0，过冲窗口更敏感。

## 6.3 工程估算

定义：

- `T_budget`：反馈更新 + 调度 + 执行的等效总延时
- `V_abs`：release 方向等效速度（counts/s）
- `Delta = V_abs * T_budget`：边界过冲估算

建议：

1. 通过日志实测 `T_budget` 与 `V_abs` 的分布。
2. 将 x1 margin 设为 `P99(Delta) + 安全冗余`。

## 6.4 改进优先级

### P0（立即执行）

1. x1 margin 改为可配置量。
2. 增加命中日志：`joint/x1/absNow/targetDeg/actualDeg/timestamp`。
3. 上电进入控制前强制重发 tendon guard 配置。

### P1（稳定性增强）

1. 引入速度相关动态 margin。
2. 增加预警边界 `x1_warn` 与硬边界 `x1_hard`。
3. 加入配置版本号与 ACK 校验。

### P2（工程完备）

1. P4 持久化 guard 配置。
2. 增加回放工具复盘边界命中时序。

## 7. 端到端运行流程（控制 + 触觉）

1. 上电初始化：任务启动、队列与互斥量初始化。
2. 上位机下发：控制使能、目标参数、x1 配置并等待 ACK。
3. 运行周期：
   1. S3 高速采集磁编并上报。
   2. P4 固定周期求解并下发电机。
   3. S3 低一档频率采集触觉 summary 并上报。
   4. P4 透传触觉到上位机，UI 用最新帧刷新。
4. 保护触发：x1 命中后进入 hold，日志记录命中快照。
5. 停止与恢复：STOP/RESET 后清理状态，下一次 START 前重发 guard。

---

## 8. 验收指标与测试矩阵

## 8.1 验收指标

1. 控制链路周期稳定度（10 ms 基线抖动统计）。
2. 磁编数据到求解输入的端到端延时分位数（P50/P95/P99）。
3. 触觉显示帧率与数据时效（age）。
4. x1 命中成功率、过冲分位数、命中后到 hold 的延时。

## 8.2 测试矩阵

1. 常速 release：连续命中与重复性。
2. 高速 release：100 次以上统计过冲分布。
3. 高通信负载：同时上报触觉与调试包，验证控制链路稳定度。
4. 重启场景：验证 guard 重发与恢复时长。
