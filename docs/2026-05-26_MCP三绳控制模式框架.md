# 2026-05-26 MCP 三绳控制模式框架

> 说明：本文档整理当前 `MCP三绳版本` 分支里的实际控制框架。它描述的是当前代码正在做的事情，不是理想化方案。

## 1. 当前控制框架一句话

当前 MCP 三绳控制是：

```text
角度目标 J00/J01
    -> 腱长模型前馈
    -> 关节角度反馈修正
    -> 每根绳基于 load 的张紧 bias 管理
    -> 电机虚拟位置目标
    -> 底层速度方式追踪该目标
```

它不是纯绳长开环，也不是真正的张力闭环。

更准确地说，它是：

```text
角度闭环 + 腱长前馈 + load 代理信号张紧管理
```

其中 `load` 不是腱张力，只是 ST3215 舵机返回的负载代理量。

## 2. 系统里的主要任务

当前固件中和控制相关的主要任务如下：

| 模块 | 作用 |
|---|---|
| `UpperCommTask` | 接收串口 / 上位机命令，解析 `start`、`degree`、角度目标、`load`、`servo`、`encoder` 等命令 |
| `StateMachineTask` | 管理系统状态：`START`、`STOP`、`RESET`、故障保持等 |
| `ControlTask` | 控制核心，每 10 ms 读取目标、角度、电机位置、load/current，并生成舵机目标 |
| `ServoCommunicationTask` | 和 ST3215 舵机通信，读取位置/load/current，并把控制目标发给电机 |
| `CanTask / EncoderTask` | 读取磁编码器，得到关节角度反馈 |

整体数据流：

```text
上位机 / 串口命令
        ↓
UpperCommTask
        ↓
sharedData.targetAngles / control_mode / command_token
        ↓
ControlTask 10 ms 周期运行
        ↓
读取磁编码器角度 + 舵机 abs/load/current
        ↓
ControlSolver 计算 MCP 三绳目标
        ↓
叠加 load 张紧 bias
        ↓
ServoTargetQueue
        ↓
ServoCommunicationTask
        ↓
ST3215 舵机执行
```

## 3. 当前有哪些控制模式

代码中主要有三类控制模式：

| 模式 | 代码名 | 串口命令 | 说明 |
|---|---|---|---|
| 关节角度模式 | `CONTROL_MODE_JOINT` | `degree` / `deg` / `joint` | 当前 MCP 三绳主要使用的模式 |
| 直接电机模式 | `CONTROL_MODE_DIRECT_MOTOR` | `direct` | 调试电机用，直接给电机目标 |
| 空闲模式 | `CONTROL_MODE_NONE` | `none` / `idle` | 不输出控制目标 |

当前你主要使用的是：

```text
CONTROL_MODE_JOINT
```

也就是角度控制模式。

## 4. 串口交互流程

推荐交互顺序：

```text
zero
start
degree
m 0 20
```

含义：

| 命令 | 作用 |
|---|---|
| `zero` | 把当前舵机位置设为软件零位，同时清空旧目标并停止控制 |
| `start` | 进入 RUNNING，使控制任务重新拥有舵机输出权 |
| `degree` | 切到关节角度模式 |
| `m 0 20` | 同时设置 J00=0 deg，J01=20 deg |

也可以单独设置某个关节：

```text
j0 0
j1 20
```

也可以同时写两个 MCP 角度：

```text
m 0 20
j 0 20
m0 0 m1 20
j0 0 j1 20
```

其中：

| 名称 | 含义 |
|---|---|
| `J00` / `m0` | MCP-AA，自由度 1 |
| `J01` / `m1` | MCP-FE，自由度 2 |

注意：

- `start` 会清空旧命令，所以一般是 `start` 之后再输入 `degree` 和角度目标。
- `zero` 会把当前电机位置作为软件零位，并且会停止控制；`zero` 后需要重新 `start`。
- `stop` 会停止控制并触发舵机急停/失能。

## 5. MCP 三绳和关节的对应关系

当前 MCP 使用 3 根绳 / 3 个电机控制 2 个关节自由度。

| 电机 | 模型中的腱 | 作用 |
|---|---|---|
| `M00` | `R tendon` | MCP 一侧绳 |
| `M01` | `L tendon` | MCP 另一侧绳 |
| `M02` | `C tendon` | 中间/辅助绳 |

代码中说明：

```text
M00 -> model R tendon
M01 -> model L tendon
M02 -> model C tendon
```

控制目标不是直接给每根绳一个固定长度，而是先从目标关节角计算三根腱的目标长度。

## 6. MCP 角度目标如何变成绳长目标

控制输入是：

```text
J00 target angle
J01 target angle
```

代码里会用几何模型计算三根腱的长度：

```text
l_R = f_R(J00, J01)
l_L = f_L(J00, J01)
l_C = f_C(J00, J01)
```

也就是：

```text
目标关节角
        ↓
三维几何腱路模型
        ↓
三根腱的目标长度
```

当前腱长到电机脉冲的比例是：

```text
kTendonLengthToPulse = -160 counts / mm
```

所以腱长变化会被换算成电机位置前馈：

```text
feedforward_counts = (target_length - zero_length) * (-160)
```

这里的 `zero_length` 是控制器初始化时记录的参考腱长。

## 7. 角度反馈修正

仅靠腱长前馈不够，因为绳子会松、会滑、会有摩擦和模型误差。

所以当前还加入了关节角度反馈：

```text
angle_error = target_angle - actual_angle
```

其中：

| 量 | 来源 |
|---|---|
| `target_angle` | 上位机输入的 J00/J01 目标 |
| `actual_angle` | 磁编码器反馈，经映射和滤波得到 |

角度误差会通过一个 3x2 的增益矩阵分配到三根绳：

```text
M00 correction = K00 * J00_error + K01 * J01_error
M01 correction = K10 * J00_error + K11 * J01_error
M02 correction = K20 * J00_error + K21 * J01_error
```

当前 PID 矩阵是：

```text
P:
M00: [-20, -30]
M01: [ 20, -30]
M02: [  0,  30]

I:
M00: [ -8, -28]
M01: [  8, -28]
M02: [  0,  28]

D:
M00: [-1, -1]
M01: [ 1, -1]
M02: [ 0,  1]
```

这说明：

- `J00` 左右摆动误差主要由 `M00/M01` 反向调节。
- `J01` 屈伸误差会同时影响三根绳。
- `M02` 主要参与 `J01` 屈伸控制。

最终基础电机目标是：

```text
solver_target = 腱长前馈 + 角度反馈修正
```

这个 `solver_target` 仍然是电机位置目标，不是张力目标，也不是扭矩目标。

## 8. load 张紧管理如何叠加

在基础 `solver_target` 之后，当前代码会对 `M00/M01/M02` 每根绳独立做 load 管理。

读取：

```text
load_abs[i] = abs(load[i])
```

当前阈值：

```text
load_low  = 80
load_high = 120
load_stop = 300
```

每根绳都有自己的：

```text
tension_bias[i]
```

逻辑是：

```text
if abs(load[i]) < 80:
    tension_bias[i] += 16

else if abs(load[i]) > 120:
    tension_bias[i] -= 16

else:
    tension_bias[i] 不变
```

限制：

```text
0 <= tension_bias[i] <= 1600
```

最终输出：

```text
final_cmd[i] = solver_target[i] + tension_direction[i] * tension_bias[i]
```

当前代码中的张紧方向是：

```text
tension_direction = [1, 1, 1]
```

因此当前默认认为三根绳的“增加 bias”方向都是收紧方向。

如果现场发现某根绳方向相反，需要改：

```text
kMcpTensionDirection
```

## 9. 当前不是“先预紧，后角度控制”

现在的控制不是：

```text
先把三根绳全部预紧
        ↓
再开始角度控制
```

而是：

```text
角度控制一直运行
load 张紧管理同时运行
```

也就是说，每个控制周期都在同时做两件事：

```text
1. 追踪 J00/J01 目标角度
2. 让每根绳的 abs(load) 尽量落在 80~120
```

这样做的原因是：

- 当前没有真实张力传感器。
- 如果做“先预紧再角度控制”，系统可能卡在预紧阶段。
- 三根绳可能一根已经紧了，另外两根还松，所以必须每根绳独立调整。

## 10. 底层电机到底怎么动

虽然上层给的是：

```text
final_cmd = 电机目标位置
```

但底层对 ST3215 的执行方式不是简单“一步跳到目标位置”。

当前底层做法更像：

```text
position_error = final_cmd - current_motor_abs
speed_command = clamp(position_error, -speed_limit, speed_limit)
发送 speed_command
```

也就是：

```text
控制层维护一个虚拟目标位置
        ↓
底层根据当前位置和目标位置的误差
        ↓
生成速度命令
        ↓
舵机逐步追踪
```

所以你在日志里看到：

```text
cmd != now
```

是正常的。

`cmd` 是当前控制器希望它去的目标位置，`now` 是舵机反馈的当前实际位置。两者之间会因为限速、负载、绳子状态而有差异。

## 11. 当前保护逻辑

### 11.1 load 过载保护

对 MCP 三个电机：

```text
if abs(load) > 300:
    锁存过载
    三个 MCP 电机 hold 当前位
    清空 tension_bias
    设置 overload_fault_bitmap
```

触发后需要：

```text
START 或 RESET
```

来清除锁存故障。

注意：`load > 300` 是经验保护阈值，不是物理张力单位。

### 11.2 MCP 电机行程保护

MCP 三个电机都有电机绝对位置保护：

```text
abs(motor_abs) <= 6400 counts
```

如果超过这个范围，会 hold MCP 电机。

### 11.3 MCP 每周期命令限幅

MCP 三个电机每个控制周期最大目标变化：

```text
max step = 320 counts / control cycle
```

控制周期是：

```text
10 ms
```

这能避免目标突然跳太大。

### 11.4 角度误差保护的当前状态

代码里普通关节仍然有：

```text
tracking error > 30 deg -> hold
```

但 MCP 的 `J00/J01` 当前跳过了这个保护。

原因是代码判断条件是：

```text
jointIndex > 1
```

所以 `J00/J01` 不会因为角度误差超过 30 度而直接 hold。

这符合你当前的实验需求：MCP 主要靠 load 过载和电机行程做保护。

### 11.5 系统级保护

状态机还会检查：

- CAN 编码器是否离线
- 舵机反馈是否离线
- 过载 fault bitmap
- 反绕保护 fault bitmap

当前调试配置下，舵机在线检查只要求：

```text
M00 / M01 / M02 在线
```

不是要求全部 22 个舵机在线。

## 12. 当前日志怎么看

典型日志：

```text
[MCP CTRL]
J00 target=...
J00 actual=...
J01 target=...
J01 actual=...
M00/R len=target/actual map=... solver=... cmd=... now=... load=... cur=... bias=...
M01/L ...
M02/C ...
```

字段含义：

| 字段 | 含义 |
|---|---|
| `J00 target` | J00 目标角 |
| `J00 actual` | J00 磁编码器反馈角 |
| `J01 target` | J01 目标角 |
| `J01 actual` | J01 磁编码器反馈角 |
| `len=target/actual` | 目标角 / 实际角分别算出来的腱长 |
| `map` | 腱长前馈 + 角度反馈后得到的基础电机目标 |
| `solver` | 求解器输出的基础电机目标 |
| `cmd` | 叠加 load bias 后实际下发的目标 |
| `now` | 当前电机反馈位置 |
| `load` | 舵机负载反馈 |
| `cur` | 舵机电流反馈 |
| `bias` | 当前该电机的张紧 bias |

最需要看的字段是：

```text
J00/J01 target vs actual
M00/M01/M02 load
M00/M01/M02 bias
cmd vs now
```

## 13. 当前框架的本质

当前框架可以理解成三层：

```text
第一层：角度目标层
    输入 J00/J01 目标角

第二层：绳长/角度求解层
    腱长模型前馈
    磁编码器角度反馈修正

第三层：张紧管理层
    每根绳独立看 abs(load)
    偏松则增加 bias
    偏紧则减少 bias
    过载则 hold
```

用一句话说：

> 角度控制决定“手指要去哪里”，load bias 决定“三根绳不要太松也不要太紧”。

## 14. 当前框架的局限

当前框架仍然有几个局限：

1. `load` 没有真实张力单位，不能等价为腱张力。
2. 当前 load 管理用的是原始 `abs(load)`，还没有做 EMA 或 rolling median 滤波。
3. 三根绳的 `load_low/load_high` 现在共用同一组阈值，尚未单独标定。
4. `tension_direction=[1,1,1]` 假设三根绳 bias 增大都是收紧方向，实际还需要现场验证。
5. 腱长几何模型仍然依赖结构参数，绳路误差、摩擦、松弛都会造成偏差。
6. 当前不是力控，也不是扭矩控，不能精确控制接触力。

## 15. 后续建议

建议下一步做三件事：

### 15.1 给 load 加滤波

例如：

```text
filtered_load[i] = 0.75 * filtered_load[i] + 0.25 * abs(load[i])
```

然后用：

```text
filtered_load
```

判断 80/120/300 阈值。

### 15.2 给三根绳分别标定阈值

例如：

```text
M00: load_low=80, load_high=120
M01: load_low=80, load_high=120
M02: 单独实验决定
```

因为 M00/M01/M02 的绳路、摩擦、方向可能不一样。

### 15.3 继续采集控制日志

建议每次实验记录：

```text
timestamp
J00 target / actual
J01 target / actual
M00 abs / cmd / load / current / bias
M01 abs / cmd / load / current / bias
M02 abs / cmd / load / current / bias
```

这样才能判断：

- 角度跟踪是否稳定
- 三根绳是否都进入 80~120
- bias 是否一直顶到 1600
- 某一根绳是否长期偏松或偏紧

## 16. 总结

当前 MCP 三绳版本的控制逻辑是：

```text
J00/J01 角度目标
        ↓
磁编码器角度反馈
        ↓
腱长几何模型前馈
        ↓
角度误差 PID 修正到三根绳
        ↓
每根绳根据 abs(load) 独立调整 tension_bias
        ↓
生成 M00/M01/M02 电机虚拟位置目标
        ↓
底层用速度方式逐步追踪目标
```

它的核心思想是：

> 用角度闭环保证手指姿态，用 load 窗口保证绳子大致绷住，用过载阈值避免拉得太狠。
