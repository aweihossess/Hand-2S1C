# 2026-07-03 训练数据采集与测试原理

## 目标

本轮修改的目标是把现有上位机从“实时查看力传感器和电机状态”扩展为“可用于后续前馈/预紧模型训练的数据采集工具”。

后续实际控制中不计划长期引入力传感器。因此当前测试阶段的力传感器主要作为监督信号和验证信号，用来建立以下关系：

- 电机相对位置、速度、load 与绳张力之间的关系。
- 手指关节角度变化过程中，绳张紧状态与电机状态之间的关系。
- 在不使用力传感器的控制阶段，如何仅通过电机位置和 load 判断预紧是否合理。

## 本轮修改记录

### 1. 力传感器通道与电机映射

已在上位机中固定记录五根绳的对应关系：

| 力传感器通道 | 对应电机 | 含义 |
| --- | --- | --- |
| CH2 | M00 | M00 绳张力 |
| CH1 | M01 | M01 绳张力 |
| CH3 | M02 | M02 绳张力 |
| CH4 | M03 | M03 绳张力 |
| CH5 | M04 | M04 绳张力 |

界面、图例、普通 CSV 导出和训练 CSV 都会保留这个映射。

### 2. 力传感器零位与单位换算

当前力传感器显示使用相对零位：

```text
relative_value = raw_value - saved_zero
force_N = relative_value / 10
```

零位记录方式：

1. 松开电机。
2. 让力传感器置于桌面，视为无拉力。
3. 点击“记录零位”。
4. 零位写入 `desktop/config/force_sensor_zero.json`，下次打开自动加载。

### 3. Encoder 机械零位

Encoder / Servo 窗口不再保存主机端相对角度零点。控制板/固件中标定的机械零位就是唯一零位：

```text
joint_deg_display = joint_deg_from_firmware
degree_target_to_device = degree_target_from_ui
```

`degree` 模式下，界面输入的是机械零位坐标下的角度；发送到下位机前不会再叠加 `zero_deg`。

旧版零点文件已废弃，并会被“固件机械零位/删除旧主机零点”按钮删除：

```text
desktop/config/encoder_zero.json
```

### 4. 新增训练数据采集区

主窗口新增“训练数据采集”区域。当前默认参数：

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| 采样间隔 | 200 ms | 每 200 ms 写一行 CSV |
| 目标周期 | 5.0 s | 每 5 秒发送一个新的覆盖式 degree 目标 |
| 关节范围 | `J0:-15:15,J1:0:30,J2:0:60,J3:-45:45` | 机械零位坐标下的 degree 目标范围，J2/J3 默认覆盖较大角度 |
| Load 保护 | 空 | 默认不使用电机 load 停机；需要备用保护时手动填入阈值 |
| 覆盖 degree 目标 | 开启 | 按关节轮流发送低位、高位、偏低、偏高、中位目标 |
| 采集前自动预紧 | 开启 | 先让五根绳达到张紧阈值 |
| 预紧目标 | -10 N | 每根绳的相对力需要进入力窗口上限，即 `force_N <= -10 N` |
| 过紧下限 | -150 N | 低于该值认为过紧，会反向放松 |
| 预紧步进 | `M00:100,M01:100,M02:100,M03:100,M04:100` | 每次调整的张紧 abs 偏置增量 |
| 预紧超时 | 20 s | 超时会停止流程并发送 `stop` |

采集文件自动保存为：

```text
run_data/training_collect_YYYYmmdd_HHMMSS.csv
```

### 5. 自动预紧逻辑

点击“开始采集”后，如果勾选“采集前自动预紧”，上位机会先进入预紧阶段，而不是立刻写 CSV。

预紧判断使用力传感器相对力：

```text
force_N = (raw_value - saved_zero) / 10
```

目标条件为：

```text
CH1..CH5 对应绳张力均在力窗口内
M00..M03 默认力窗口 = -150 N <= force_N <= -10 N
M04/CH5 力窗口 = -20 N <= force_N <= -10 N
```

上位机每轮检查 CH1-CH5：

| 若某通道已达标 | 行为 |
| --- | --- |
| M00..M03: `-150 N <= force_N <= -10 N` | 对应电机不动 |
| M04/CH5: `-20 N <= force_N <= -10 N` | M04 不动 |
| `force_N > -10 N` | 绳太松，对应电机增加一次张紧 abs 偏置 |
| M00..M03: `force_N < -150 N` | 绳太紧，对应电机减小一次张紧 abs 偏置 |
| M04/CH5: `force_N < -20 N` | M04 过紧，减小 M04 张紧 abs 偏置 |

对应关系仍为：

```text
CH2 -> M00
CH1 -> M01
CH3 -> M02
CH4 -> M03
CH5 -> M04
```

例如 CH3 当前为 `-4 N`，目标窗口为 `-150 N <= force_N <= -10 N`，则上位机会张紧 M02；如果 CH5 当前为 `-4 N`，则会张紧 M04；如果 CH5 已经为 `-38 N`，则 M04 会反向放松，因为 M04 只允许保持在 `-20 N..-10 N`。

预紧指令使用固件中的同一个 tension bias，不切换到 direct 模式。默认偏置步进为：

```text
M00:100,M01:100,M02:100,M03:100,M04:100
```

Bias 行程限幅为：

```text
M00..M04: -7200..7200 counts
```

如果某根绳越动越松，说明该电机方向相反，应把对应项改成负数，例如：

```text
M01:-20
```

预紧阶段负责把绳拉入力窗口。全部通道达标后，上位机才创建训练 CSV，并进入 degree 目标采集阶段。采集过程中如果勾选自动预紧，上位机会继续按同一力窗口维护张力，维护动作通过 `tensionbias mX value` 叠加到 degree 控制输出上。

如果预紧或采集维护过程中触发 load 保护、力传感器数据超时或超过超时时间，上位机会停止流程并发送 `stop`。

### 6. Load 保护

训练采集时默认只监控五根绳对应的电机：

```text
M00, M01, M02, M03, M04
```

如果手动填入 `Load保护(abs)` 阈值，且任意一个电机满足：

```text
abs(load) > Load保护阈值
```

上位机会：

1. 停止继续写训练 CSV。
2. 向 Encoder / Servo 控制板发送一次 `stop`。
3. 在采集状态中显示触发保护的电机和 load 值。

### 7. 启动命令

当前文档中的启动方式已统一为：

```powershell
& 'C:\Users\A\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' .\desktop\force_sensor_monitor.py --port COM7
```

力传感器使用 COM7。Encoder / Servo 串口在第二个窗口中手动选择并连接。

## 当前测试原理

### 核心思路

当前实验不是为了让每个关节精确到达某个单点，而是为了让手指在绳处于张紧状态时覆盖尽可能多的运动状态。

测试时，上位机会周期性给某个关节发送一个安全范围内的覆盖式 `degree` 目标。目标按关节轮流切换，并优先覆盖低位、高位、偏低、偏高、中位，从而减少 J2/J3 长时间停在零点附近的问题。电机和手指在运动过程中会产生一段连续轨迹。上位机在轨迹中按固定频率记录：

- 电机位置。
- 电机速度。
- 电机 load。
- Encoder 角度。
- 力传感器读数。
- 由力传感器换算得到的绳张力。

这样得到的数据不是孤立点，而是运动过程中的时序样本。

### 为什么要记录运动过程

绳驱系统存在摩擦、回差、松弛、方向相关性和速度相关性。仅记录静止点会漏掉很多真实控制中会遇到的状态。

运动过程数据可以覆盖：

- 拉紧和放松方向不同导致的张力差异。
- 同一位置下，不同速度和 load 对张力的影响。
- 绳由松到紧的过渡区。
- 电机命令、实际位置、关节角度之间的延迟。

这些信息对后续建立前馈模型更有价值。

### 为什么未来控制不直接依赖力传感器

当前力传感器更适合作为实验阶段的标定工具。未来实际控制阶段希望减少外部传感器依赖，仅使用电机已有反馈进行预紧判断。

因此训练数据中的典型角色是：

| 数据 | 训练阶段作用 | 未来控制阶段作用 |
| --- | --- | --- |
| 力传感器张力 | 监督标签 / 验证指标 | 不直接使用 |
| 电机相对位置 | 模型输入 | 实时输入 |
| 电机速度 | 模型输入 | 实时输入 |
| 电机 load | 模型输入 | 实时输入 |
| Encoder 角度 | 模型输入或状态参考 | 若实际系统保留 encoder，则可用；否则可作为训练辅助 |

更理想的模型目标不是简单预测一个绝对力值，而是辅助判断：

- 当前绳是否已经预紧。
- 当前运动方向下是否可能松绳。
- 某个关节目标附近需要多少电机前馈补偿。
- 不同手指姿态下，电机 load 到张力的关系是否稳定。

## CSV 数据含义

训练 CSV 的字段很多，主要分为四类。

### 1. 时间与目标

| 字段 | 含义 |
| --- | --- |
| `timestamp` | 主机时间戳 |
| `local_time` | 本地可读时间 |
| `elapsed_s` | 本次采集开始后的秒数 |
| `target_mode` | 自动目标模式：`coverage`、`single`、`combo`、`roundtrip` 或 `step` |
| `target_phase` | 当前目标阶段，例如 `single_j02`、`combo_01`、`roundtrip_j03_2`、`step_10_20_20_35` |
| `target_joint` | 最近一次自动目标关节 |
| `target_relative_deg` | 最近一次自动目标角度；字段名历史遗留，当前等同于机械零位 degree |
| `target_device_deg` | 实际发送给设备的 degree；当前与 `target_relative_deg` 相同 |
| `target_command` | 实际发送给下位机的文本命令；批量目标会用 `|` 连接 |
| `tension_window_ok` | 本轮检测时 M00..M03 是否在 `-150 N..-10 N`、M04/CH5 是否在 `-20 N..-10 N` 窗口内 |
| `tension_action` | 上位机本轮发出的张力维护动作，例如 loose/tight 和对应 motor bias |
| `tension_action_count` | 本次采集累计张力维护动作数 |
| `tension_bias_m00_counts`..`tension_bias_m04_counts` | 上位机按力传感器维护出的 tension bias |
| `target_j00_relative_deg`..`target_j20_relative_deg` | 当前采集流程维护的完整 joint 目标向量 |
| `target_j00_known`..`target_j20_known` | 该 joint 目标是否已知；训练 J00-J03 时建议只使用 known=1 的样本 |

### 2. 力传感器原始通道

示例字段：

```text
force_ch1_raw
force_ch1_relative
force_ch1_n
force_ch1_age_s
```

`age_s` 表示当前 CSV 行使用的力传感器样本距离写入时刻有多旧，用于判断同步误差。

### 3. 按电机映射后的张力

示例字段：

```text
tension_m00_channel
tension_m00_relative
tension_m00_n
```

这类字段已经把 CH 映射成对应电机，更方便后续按绳/电机训练模型。

### 4. Encoder 与 Servo 状态

Encoder 示例字段：

```text
joint_j00_raw
joint_j00_mapped
joint_j00_deg_abs
joint_j00_deg_rel
joint_j00_valid
```

`joint_j00_deg_rel` 是历史字段名，当前与 `joint_j00_deg_abs` 相同，表示固件机械零位坐标下的角度。

Servo 示例字段：

```text
servo_m00_abs
servo_m00_hardware_abs
servo_m00_zero_offset
servo_m00_raw
servo_m00_speed
servo_m00_load
servo_m00_voltage
servo_m00_temperature
servo_m00_online
```

## 建议测试流程

1. 关闭官方力传感器上位机，避免 COM7 被占用。
2. 启动本上位机并连接 COM7。
3. 松开电机，力传感器无拉力，点击“记录零位”。
4. 打开 Encoder / Servo 窗口，连接控制板串口。
5. 确认固件/控制板已经完成机械零位标定；上位机不再记录第二套角度零点。
6. 检查 `START`、`STOP`、手动 degree/direct 指令是否正常。
7. 将训练采集的关节范围设为较保守范围。
8. `Load保护(abs)` 默认留空，不再用电机 load 作为采集停机条件；当前主要依据力传感器张力窗口判断。
9. 检查预紧步进方向。如果某根绳方向相反，把对应 `Mxx` 步进改成负数。
10. 手动按 `START` 后点击“开始采集”。
11. 上位机会先自动预紧，全部绳达到目标后再开始写 CSV。
12. 观察力曲线、load、关节角度，必要时手动停止。
13. 采集结束后检查 `run_data` 下的 CSV。

## 当前关节级模型采集建议

当前目标先不是直接学习指尖位置，而是学习 J00-J03 的关节级补偿。建议每轮采集按以下顺序执行：

1. **零位和预紧段**：记录力传感器零位、Encoder 零点、Servo 软件零点；保持 `tension on`，让每根绳达到预紧阈值。
2. **小范围单关节段**：一次只明显改变一个 joint，其它 joint 保持接近 0，用于识别每根绳对单关节的主要作用。
3. **组合姿态段**：让 J00-J03 形成组合目标，例如 J02/J03 大角度而 J00/J01 小角度、J01 大角度而 J02/J03 中等角度，用于识别耦合。
4. **往返动态段**：同一组目标要从低到高、再从高到低各采一次，用于覆盖绳驱回差、摩擦和方向相关性。
5. **保持段**：每个目标附近至少保持 2-5 s，用于区分瞬态误差和稳态误差。

上位机 `mode` 下拉与上述采集段的对应关系：

| mode | 对应采集段 |
| --- | --- |
| `coverage` | 快速覆盖角度范围，适合确认安全范围和初步铺数据 |
| `single` | 小范围单关节段 |
| `combo` | 组合姿态段 |
| `roundtrip` | 往返动态段 |
| `step` | 固定阶跃段：J00-J03 一次发送 `[10, 20, 20, 35]` 并保持 |

推荐采集设置：

| 项目 | 建议 |
| --- | --- |
| 采样间隔 | 100-200 ms；如果要估计速度/加速度，优先 100 ms |
| 目标周期 | 5-8 s，先慢后快 |
| Load保护 | 默认关闭；如需备用保护可手动填入阈值 |
| `tension` | 先固定为 `on` 做一批，再做 `off` 对照批 |
| `ff` | 根据实验目的固定，不要一段数据里频繁切换 |

训练时建议优先使用：

```text
输入:
  target_j00..j03_relative_deg  # 历史字段名，实际为机械零位 degree
  joint_j00..j03_deg_rel        # 历史字段名，实际为机械零位 degree
  joint error = target - actual
  servo_m00..m04_abs
  servo_m00..m04_speed
  servo_m00..m04_load
  最近 0.6-1.0 s 历史窗口

输出:
  每个电机的 correction / bias
  或下一时刻关节误差趋势
```

不要把明显异常的数据直接用于训练，例如：

1. 任一 `joint_j00..j03_valid=0` 的行。
2. `encoder_age_s` 或 `force_chX_age_s` 明显过大。
3. Load 已触发保护或接近机械危险区。
4. 目标刚切换后的极短冲击段，如果当前模型只想学稳态补偿，可先剔除前 0.5-1.0 s。

## 数据质量注意事项

1. 每次实验前都要重新确认力传感器零位。
2. 如果机械状态发生改变，例如绳长、绑扎位置、摩擦状态改变，应重新采集数据。
3. 训练数据应覆盖拉紧方向和放松方向。
4. 不要只采集低速、单方向、单姿态数据，否则模型会过拟合。
5. 如果发现 `encoder_age_s` 或 `force_chX_age_s` 明显变大，说明某一路通讯刷新变慢，应暂停使用该段数据。
6. 如果 load 已经接近保护阈值，不应扩大关节范围。
7. 力传感器标签可能包含延迟，后续训练时可以考虑加入时间窗口特征，而不是只用单帧输入。

## 当前局限

1. 上位机采集是软实时同步，不是硬实时同步；CSV 中使用最新样本并记录 age。
2. 覆盖式目标目前仍是阶跃式切换，不是轨迹规划器。
3. Load 单位仍按控制板上报原值记录，尚未标定成物理单位。
4. 目前默认覆盖目标只覆盖 J0-J3，后续需要根据安全范围逐步扩展。
5. 当前模型设计仍处在数据采集阶段，训练目标和评价指标需要根据第一批数据分布再确定。

## 后续建议

第一批数据建议先做小范围、短时长测试。重点不是马上训练大模型，而是先验证：

- 张力标签是否稳定。
- load 和张力是否存在可学习关系。
- 同一关节角度下，运动方向是否显著影响张力。
- 是否需要把速度、方向、历史窗口加入模型输入。

如果上述关系明显存在，再进入较大范围、多轮次的数据采集。
