# 2026-05-25 电机 load/current 实验总结（飞书导入版）

> 说明：本文档用于整理 2026-05-25 的 ST3215 舵机 `load/current` 实验。Markdown 中保留了本地图片路径，导入飞书后如果图片没有自动显示，可以按文件名从 `run_data/` 目录手动插入。

## 1. 实验目的

当前手指控制系统没有腱张力传感器，只有：

- 舵机位置 / 目标位置
- 舵机 `load`
- 舵机 `current`
- 关节磁编码器角度

本轮实验想验证的问题是：

- 电机静止时，外力拉紧绳子是否会反映到 `load/current`。
- 电机主动收线时，`load/current` 是否能区分松绳、轻微张紧、明显张紧。
- 后续能否用 `load` 作为“绳子是否绷紧”的代理信号。
- 后续能否用 `load` 做自动张紧和过载保护。

核心结论：

> 静态外力几乎不能稳定反映到 `load/current`；但在电机主动收线时，`load` 对绳子受力变化有可用响应，明显优于 `current`。因此控制里应把 `load` 当作张紧状态的弱代理信号，而不是精确张力传感器。

## 2. 实验环境与采样频率

实验使用 PC 侧脚本：

```text
tools/low_tension_takeup/low_tension_takeup.py
```

配置中：

```text
period_s = 0.02
```

理论采样 / 控制频率：

```text
1 / 0.02 = 50 Hz
```

但实际每一轮都要通过串口请求：

```text
servo
load
encoder
```

然后等待返回、解析、写 CSV、再发送目标位置。因此实际频率约为：

```text
7 Hz
```

这说明：

- 当前 PC 脚本适合低速实验和离线分析。
- 当前 PC 脚本不适合直接作为高频实时控制器。
- 最终实时控制逻辑应该尽量放到 ESP32 固件里运行。
- 因为实际只有约 7 Hz，瞬态变化和很短时间的峰值可能会被漏采。

## 3. 信号含义

### 3.1 load

`load` 是 ST3215 返回的负载相关寄存器值。

实验中主要使用：

```text
effective_load = abs(load - idle_load)
```

在多数实验里 `idle_load` 接近 0，所以可以近似理解为：

```text
effective_load ≈ abs(load)
```

注意：

- `load` 不是腱张力。
- `load` 不是关节扭矩。
- 它只是“电机输出负载状态”的代理量。
- 在主动收线时，它能反映绳子是否开始吃力。
- 在电机静止时，它不一定能反映外部拉绳造成的张力。

### 3.2 current

`current` 是 ST3215 返回的电流反馈值。

ST3215-C018 中近似换算为：

```text
1 current count ≈ 6.5 mA
```

实验中 `current` 的变化通常比较小。

例如 M01 高负载主动收线实验中：

```text
current_max = 24 count
effective_current_mA_max ≈ 156 mA
```

这个电流不大，说明它不能单独作为可靠的张力判断依据。当前更适合把 `current` 当作辅助观察量，而不是主控制量。

主要观察：

- `cumulative bias` 是脚本累计发出的命令行程，不等于电机真实走过的绝对位置。
- `load raw` 和 `effective load` 近似镜像，是因为 raw load 为负，而 effective load 取了绝对值。
- `current` 有变化，但幅度较小。
- `load-current` 散点图显示二者有一定相关性，但 `load` 的动态范围更大。

结论：

> 主动收线时，`load` 可以反映绳子受力变化；`current` 也会变化，但更弱。

## 6. 从实验得到的控制策略

### 6.1 不采用静态张力判断

静态保持测试表明：

```text
电机不动 + 手动拉绳
```

并不会稳定反映到 `load/current`。

因此不能使用：

```text
电机保持不动时读取 load/current 判断绳是否绷紧
```

### 6.2 使用主动收线时的 load

更可靠的方式是：

```text
电机主动小步收线
观察 load 是否上升
```

所以控制策略应是：

```text
角度控制给出基础电机目标
load 管理在基础目标上叠加 bias
load 低于窗口时略微收紧
load 高于窗口时略微释放
load 过高时停止继续拉
```

### 6.3 当前推荐 load 窗口

结合 M02 和 M01 实验，当前建议先使用：

```text
目标窗口：abs(load) = 80~120
保护阈值：abs(load) > 300
```

含义：

```text
abs(load) < 80:
    认为该绳偏松，增加 tension bias

80 <= abs(load) <= 120:
    认为张力合适，保持 tension bias

abs(load) > 120:
    认为该绳偏紧，减少 tension bias

abs(load) > 300:
    认为负载过大，MCP 三电机 hold / stop
```

注意：`80~120` 不是物理张力单位，而是当前实验下的舵机负载经验窗口。

### 6.4 每根绳要单独管理

MCP 三绳结构里可能出现：

```text
一根绳已经很紧，其余两根仍然偏松
```

所以不能只看三根绳的平均 `load`。

更合理的是：

```text
M00 单独判断 abs(load)
M01 单独判断 abs(load)
M02 单独判断 abs(load)
```

也就是每根绳都有自己的 bias：

```text
final_cmd[i] = angle_model_cmd[i] + tension_bias[i]
```

并且每根绳独立做：

```text
偏松 -> 自己继续收紧
合适 -> 自己保持
偏紧 -> 自己释放一点
过载 -> 整体保护
```

### 6.5 为什么不是直接做真正张力控制

因为当前系统没有腱张力传感器。

所以现在的控制不是：

```text
真实张力闭环控制
```

而是：

```text
角度闭环 + load 代理信号张紧管理
```

`load` 只能用来判断：

- 绳子是否可能偏松
- 电机是否明显吃力
- 是否接近过载风险

不能用来精确计算：

- 腱张力
- 关节扭矩
- 接触力

## 7. 对当前 MCP 三绳控制的影响

实验后控制框架采用以下思路：

```text
目标角度 J00/J01
        ↓
腱长模型 / 角度反馈得到基础电机目标
        ↓
读取 M00/M01/M02 的 load
        ↓
根据每根电机的 abs(load) 调整各自 tension bias
        ↓
输出最终电机目标
```

当前策略是：

```text
角度控制一直运行
load 管理只作为输出层张紧修正
```

也就是说不是：

```text
先预紧，后角度控制
```

而是：

```text
角度控制和张紧管理同时运行
```

这样可以避免系统卡在预紧阶段，也更符合当前没有真实张力传感器的硬件条件。

## 8. 建议加入的控制伪代码

建议在固件中对每根电机做类似逻辑：

```text
filtered_load[i] = 0.75 * filtered_load[i] + 0.25 * abs(load[i])

if filtered_load[i] < 80:
    tension_bias[i] += bias_step

else if filtered_load[i] > 120:
    tension_bias[i] -= release_step

else:
    tension_bias[i] = tension_bias[i]

if filtered_load[i] > 300:
    hold_all_mcp_motors()

final_cmd[i] = angle_cmd[i] + tighten_sign[i] * tension_bias[i]
```

建议初始参数：

| 参数 | 建议值 | 说明 |
|---|---:|---|
| `load_low` | 80 | 低于该值认为偏松 |
| `load_high` | 120 | 高于该值认为偏紧 |
| `load_stop` | 300 | 保护停止阈值 |
| `bias_step` | 4 或 8 | 偏松时每周期收紧步长 |
| `release_step` | 4 或 8 | 偏紧时每周期释放步长 |
| `EMA alpha` | 0.25 | load 滤波系数 |

## 9. 后续建议

### 9.1 对 load 做滤波

当前 `load` 波动明显，建议在固件中使用 EMA：

```text
filtered_load = 0.75 * filtered_load + 0.25 * abs(load)
```

之后用 `filtered_load` 判断 `80~120` 窗口。

### 9.2 对不同电机分别标定阈值

M00/M01/M02 的走线、摩擦、拉紧方向和负载方向不同。

后续可以考虑：

```text
M00: 单独 idle_load、load_low、load_high
M01: 单独 idle_load、load_low、load_high
M02: 单独 idle_load、load_low、load_high
```

尤其 M02 在实验中经常表现出更明显的 `load/current` 响应。

### 9.3 建立更完整的数据集

后续应继续采集：

```text
不同关节角度
不同绳长状态
不同手动外力
不同目标速度
不同 bias_step
```

并记录：

```text
timestamp
J00/J01 angle
M00/M01/M02 abs
M00/M01/M02 target
M00/M01/M02 load
M00/M01/M02 current
M00/M01/M02 bias
```

这样才能判断 `load` 是否能在更广泛姿态下稳定作为张紧管理信号。

## 10. 一句话总结

> 这轮实验说明：ST3215 的 `load/current` 不能作为静态张力传感器使用，但在主动收线过程中，`load` 对绳子受力变化有可用响应。因此当前最合理的控制方式是“角度控制为主，load 窗口管理为辅”，让三根绳的 `abs(load)` 尽量维持在 `80~120`，并在超过 `300` 时触发保护。
