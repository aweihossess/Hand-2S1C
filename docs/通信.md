## 3. 数据帧定义

### 帧编号：COM_FRAME_PC_TO_P4_COMMAND

1. 用途：上位机向 P4 下发控制命令。
2. 发送端：`desktop/protocol.py` 的 `_build_command_frame()` 及各 `build_*_cmd()`。
3. 接收端：`ESP32-P4/ServoBoardMain/UpperCommTask.cpp` 的 `handleSerialByte()`、`handleCommand()`。
4. 触发时机：UI 或控制脚本调用 `HandController`，由 `LowerComputerComm._tx_loop()` 写串口。
5. 代码位置：`protocol.py`、`comm_layer.py`、`core_logic.py`、`UpperCommTask.cpp`。
6. 帧格式：

| 字段 | 字节范围或字段名 | 类型 | 含义 | 单位 | 取值范围 | 代码依据 |
| -- | -- | -- | -- | -- | -- | -- |
| Header | byte0 | `uint8` | 帧头 | 无 | `0xFE` | `protocol.py`、`UpperCommTask.cpp` |
| Len | byte1 | `uint8` | 从 CMD 到 Tail 的字节数 | 字节 | `1 + payload_len + 1` | `_build_command_frame()`、P4 parser |
| CMD | byte2 | `uint8` | 命令字 | 无 | 见下表 | `CMD_*` |
| Payload | byte3.. | bytes | 命令数据 | 依命令 | 依命令 | `build_*_cmd()`、`handleCommand()` |
| Tail | 最后 1 字节 | `uint8` | 帧尾 | 无 | `0xFF` | `protocol.py`、`UpperCommTask.cpp` |

| CMD | 名称 | Payload | 字节序 | P4 行为 | 代码依据 |
| -- | -- | -- | -- | -- | -- |
| `0xCA` | `CMD_CALIBRATE` | 0 字节 | 无 | 当前仅设置 UI 标定状态为空闲 | `UpperCommTask.cpp` |
| `0xCB` | `CMD_ANGLE_CTRL` | 21 个 `float32` | little-endian | 写入 `targetAngles`，控制模式切到关节模式 | `protocol.py`、`UpperCommTask.cpp` |
| `0xCC` | `CMD_START` | 0 字节 | 无 | `controlEnabled=true`，清故障 token | `UpperCommTask.cpp` |
| `0xCD` | `CMD_STOP` | 0 字节 | 无 | `controlEnabled=false` | `UpperCommTask.cpp` |
| `0xCE` | `CMD_RESET` | 0 字节 | 无 | 清目标、禁用控制、回关节模式 | `UpperCommTask.cpp` |
| `0xCF` | `CMD_CALIB_DATA` | 21 个 `float32` | little-endian | 写入 `calib_zero_raw_cache` | `protocol.py`、`UpperCommTask.cpp` |
| `0xD0` | `CMD_MOTOR_POS` | 22 个 `int16` | big-endian | 写入单圈电机目标 | `protocol.py`、`UpperCommTask.cpp` |
| `0xD1` | `CMD_SENSOR_STREAM_MODE` | 1 个 `uint8` | 无 | 设置传感器流模式并 ACK | `protocol.py`、`UpperCommTask.cpp` |
| `0xD2` | `CMD_MOTOR_POS_SWEEP` | 22 个 `int16` | big-endian | 写入 sweep 电机目标 | `protocol.py`、`UpperCommTask.cpp` |
| `0xD3` | `CMD_MOTOR_POS_ABS` | 22 个 `int16` | big-endian | 写入绝对电机目标，后续限幅到 `-30719..30719` | `protocol.py`、`UpperCommTask.cpp`、`AngleSolver.cpp` |
| `0xD4` | `CMD_TENDON_GUARD` | 21 组，每组 4 字节 | 混合 | 写入腱保护配置 | `protocol.py`、`UpperCommTask.cpp` |

7. 示例数据：未在当前代码中找到明确示例；上表为格式模板。
8. 校验方式：检查帧头、长度、帧尾和固定 payload 长度；未见 checksum 或 CRC。
9. 解析流程：`handleSerialByte()` 组帧，`handleCommand()` 分发，写入 `TaskSharedData_t`。
10. 发送流程：上位机 `LowerComputerComm.send_command()` 入队，`_tx_loop()` 调 `serial.write()`。

## 7. 最小通信验证顺序

1. P4 单板串口：验证 COM-01 的 `PACKET_PROTO_ACK`、`PACKET_SENSOR` 外层帧解析。
2. 上位机到 P4 命令：用 `LowerComputerComm` 发送 `CMD_SENSOR_STREAM_MODE`、`START`、`STOP`。
3. P4 到舵机：逐总线验证 COM-02 读位置，再小幅写目标。
4. S3 编码器 SPI：单独确认 COM-03 的 21 路 raw 和错误码。
5. S3 到 P4 CAN：验证 COM-04 的 `0x100..0x105` 编码器帧和 `0x1F0..0x1F2` 错误帧。
6. P4 控制闭环：在编码器和舵机都可用后验证 DF-04，重点看 J16 双舵机。
7. P4 到上位机调试反馈：验证 COM_FRAME_P4_SERVO_ANGLE、COM_FRAME_P4_SERVO_TELEM、COM_FRAME_P4_JOINT_DEBUG。
8. 独立触觉 SPI：先运行 COM-06 的 Paxini 草图，确认真实 payload 和 CRC。
9. 触觉 CAN 集成：统一 COM-07 的 CAN ID、seq、DLC 和调用点，再验证 P4 `PACKET_TACTILE`。
10. 完整上位机控制：用 GUI 做最小开合动作，记录串口、CAN、舵机在线、编码器角度和故障位图。
